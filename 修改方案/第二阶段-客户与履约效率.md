# 第二阶段：客户与履约效率

## 1. 阶段目标

在第一阶段预约状态稳定后，解决服务者每天最实际的三类问题：

```text
收了多少钱 -> 拍摄准备是否完成 -> 客户和订单如何持续跟进
```

本阶段把应用从“能排单”提升为“能管理一次完整拍摄服务”。

## 2. 前置依赖

本阶段依赖第一阶段已经具备：

- 可靠的订单状态；
- 预约确认和取消流程；
- 订单操作日志；
- 通知中心；
- 服务项目与订单的稳定关联。

## 3. 收款与账务

### 功能

- 订单总价；
- 定金应收和实收；
- 尾款应收和实收；
- 分次收款；
- 收款时间；
- 收款方式；
- 退款记录；
- 欠款金额；
- 尾款提醒。

### 页面

- 排单详情增加收款进度；
- 新增订单收款记录弹窗；
- 新增“待收款”列表；
- 我的页面增加本月收入和待收款统计。

### 规则

- 支付状态由收款记录计算，不再只依赖一个金额字段。
- 已完成订单仍允许补录尾款，但必须留下操作记录。
- 删除订单不能删除历史收款记录。

## 4. 客户档案升级

长期客户和临时客户保留现有区分，并增加：

- 客户来源；
- 客户标签；
- 风格偏好；
- 禁忌项；
- 历史拍摄次数；
- 累计消费金额；
- 最近拍摄时间；
- 下次回访时间；
- 客户备注时间线。

客户详情页应能直接看到：

```text
客户基本资料 -> 历史订单 -> 收款记录 -> 备注变更 -> 下次跟进
```

增加手机号重复检测，避免同一客户被重复创建。

## 5. 拍摄准备清单

订单详情增加可勾选清单：

- 已确认拍摄时间；
- 已确认拍摄地点；
- 已确认服装；
- 已确认妆造；
- 已查看参考图；
- 已收定金；
- 已准备设备；
- 已通知客户；
- 已完成拍摄。

不同服务类型可以有不同清单模板，例如摄影、妆造和商业拍摄使用不同项目。

支持在订单完成前显示未完成事项，减少漏带设备、漏确认地点和漏收尾款等问题。

## 6. 服务套餐和报价

服务者可以维护套餐：

- 套餐名称；
- 服务类型；
- 服务时长；
- 服务价格；
- 定金比例；
- 包含内容；
- 超时费用；
- 是否公开展示。

公开约拍时，公开预约用户先选择套餐，再选择服务者和时间。套餐时长应直接影响可预约时间计算。

第一版只做服务者手动维护套餐，不做复杂营销优惠和会员体系。

## 7. 后期交付跟踪

订单完成后增加交付状态：

```text
待选片 -> 选片中 -> 修图中 -> 初稿待确认 -> 终稿完成 -> 已交付
```

每个状态支持：

- 负责人；
- 截止日期；
- 备注；
- 通知客户；
- 交付链接。

客户可以通过安全链接查看交付状态，服务者可以快速识别逾期订单。

## 8. 数据备份和导出

实现设置页中“自动备份”开关对应的真实功能：

- 手动导出客户和订单 JSON/CSV；
- 导出指定日期范围；
- 自动备份执行记录；
- 最近一次备份时间；
- 数据恢复前二次确认。

备份文件不得暴露在公开订单接口中，下载需要登录和权限校验。

## 9. 验收标准

1. 一笔订单可以记录多次收款和退款。
2. 可以准确计算应收、已收和待收金额。
3. 客户详情可以查看历史订单和消费记录。
4. 订单可以使用服务类型对应的拍摄准备清单。
5. 套餐时长会参与档期冲突计算。
6. 订单完成后可以跟踪选片、修图和交付状态。
7. 客户和订单数据可以导出，并且导出接口具备权限控制。

## 10. 本阶段暂不实施

- 复杂财务报表；
- 在线支付平台接入；
- 自动开发票；
- CRM 群发营销；
- 会员积分和优惠券。
