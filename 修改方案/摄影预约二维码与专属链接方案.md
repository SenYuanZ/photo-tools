# 摄影预约二维码与专属链接方案

日期：2026-10-09

状态：方案阶段，尚未实施。具体路由、字段和接口名称需对照现有代码确认。

## 一、目标

服务者登录后，一键生成自己的摄影预约二维码和预约链接。客户扫描二维码或访问复制的链接，进入现有「预约拍摄」页面，并自动选中对应服务者。客户提交后，预约直接登记到所选服务者名下。

## 二、服务者生成入口

在「我的」页面增加「我的预约二维码」入口，展示：

- 当前服务者的头像、姓名。
- 专属预约二维码。
- 「保存二维码」「复制预约链接」两个按钮。

生成时，以当前登录账号关联的服务者身份为准。如果账号没有服务者身份，提示先完成服务者资料。

链接示例（实际地址以现有预约路由为准）：

```text
https://你的域名/预约入口?provider=公开标识
```

二维码内容就是这条链接，因此扫码与复制链接访问的效果一致。链接使用稳定的公开标识，不包含登录 token、手机号或其他私密信息。

## 三、扫码后的预约流程

```text
扫描二维码 / 打开复制的链接
            ↓
进入预约拍摄页面
            ↓
解析服务者标识，查询服务者资料
            ↓
自动选中对应服务者，显示姓名与头像
            ↓
填写拍摄时间、地点等信息
            ↓
提交预约，登记到该服务者名下
```

推荐默认选中后仍允许手动更换服务者。页面可以显示简短提示：`已为你选择摄影师：张三`。

通过普通预约入口进入时，继续使用原来的服务者选择流程。

## 四、登录与链接选择的关系

| 场景 | 处理方式 |
| --- | --- |
| 服务者登录后生成二维码 | 使用该账号关联的服务者身份生成链接 |
| 客户已登录后打开链接 | 使用链接指定的服务者，客户账号负责填写预约人信息 |
| 客户未登录后打开链接 | 先选中服务者；如果提交需要登录，登录后返回原预约页面并保留选择 |
| 登录账号已有默认服务者 | 链接指定的服务者优先；客户后续可以手动更换 |

登录跳转不能丢失链接参数，页面加载默认值也不能覆盖链接指定的服务者。客户后续手动更换后，以客户最终选择为准。

## 五、实现重点

### 前端

- 复用现有预约页面，在初始化时读取 `provider` 参数。
- 查询并验证服务者后，写入预约表单的服务者字段。
- 二维码与复制链接共用同一个链接生成函数。
- 登录返回保留完整预约地址；若中途填写了表单，也保留草稿。
- 服务者信息加载完成前，禁止提交，避免误登记到其他人名下。

### 后端

- 提供按公开标识查询服务者的能力，只返回预约页面需要的公开资料。
- 提交预约时再次检查服务者是否存在、是否可接受预约。
- 公开链接只负责选人，不能授予修改服务者资料或查看其订单的权限。

服务者不存在、停用或不再接单时，明确提示「该服务者暂时无法预约」，并提供重新选择入口，避免静默改选。

现有标识及接口是否可以复用，需要检查代码后确定；如需新增公开标识，应明确数据库和 API 合同变化。

## 六、首期范围与验收

首期完成「个人二维码展示、保存二维码、复制链接、自动选中、登录后保留选择」即可。二维码长期有效，服务者改名或换头像后，无须重新生成。

验收重点：

- 扫码与复制链接，都能选中同一服务者。
- 客户已登录、未登录再登录，两种情况选择都正确。
- 账号默认值不会覆盖链接指定的服务者。
- 客户手动更换后，提交采用最终选择。
- 提交后的预约确实归属所选服务者。
- 无效链接有明确提示，不会静默改选。
- 普通预约入口仍能正常手动选择服务者。
- 二维码保存与链接复制在移动端可用。
